**Confirmed** means inspected code, retrieved official text or a named executed
check. It does not mean an end-to-end exploit was demonstrated. **Inferred**
identifies an impact, threat or recommendation. **Unknown** identifies missing
runtime, sample, contractual or measurement evidence. High severity blocks a
stated client confidentiality, financial integrity or launch requirement; medium
requires a bounded fix, procedure or explicit service limitation; low is
maintenance/documentation debt. Severity is assessed against the proposed
advisory service, rather than personal single-owner use.

**Architecture impact:** documentation only. No application authentication,
network/provider settings, foreground/background timing, persistence/events,
business-logic ownership, retries or user-edit precedence changed. No finding is
fixed by this PR: **fix not verified** for all proposed remedies. Tests below
are future requirements unless explicitly marked executed.

## Review and validation boundaries

The full surface inventory and negative-test families T01–T14 are in
[permissions-threat-model.md](permissions-threat-model.md). Denial tests must
inspect persistence, files, events, secrets, caches, tool output and outbound
calls as well as HTTP status. Preserve disabled-provider silence, local
resolution, failure isolation and concurrent user edits; their complete runtime
guarantees are unverified here.

Executed evidence is limited to launcher tests (4), Python CI-script unit tests
(22), and the bank lane's audit-only helper assertions (7). Passing script tests
do not prove container encryption or DR; passing assertions intentionally
reproduce current permissive behavior, not fixes. Focused pnpm attempts did not
run the requested Vitest tests. Toolchain mismatch/missing Rust/container
prerequisites and final PR-revision reviews are recorded in
[baseline.md](baseline.md) and [coordination/review.md](coordination/review.md).
No real client data, credential or exploit was used.
